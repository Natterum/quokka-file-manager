# Архитектура Quokka File Manager

Приложение — одно окно на `eframe` (immediate-mode UI egui). Состояние хранится в `QuokkaApp`, каждый кадр перерисовывается целиком из этого состояния.

## Модули

| Модуль         | Ответственность |
|----------------|-----------------|
| `main.rs`      | Создаёт окно (1400×860, минимум 960×600), ставит иконку из логотипа, запускает `QuokkaApp`. В release на Windows отключает консоль (`windows_subsystem = "windows"`). |
| `app.rs`       | Всё, что видно на экране: верхняя панель, сайдбар, панели с вкладками, таблица файлов, F-бар, модальные диалоги, тосты, прогресс операций. Обработка клавиатуры и диспетчеризация действий. |
| `panel.rs`     | `Panel` — модель одной вкладки: путь, список `Entry`, курсор, отметки, фильтр, сортировка, история, статистика диска. Не зависит от UI. |
| `fsops.rs`     | Фоновые задачи (`Job`): копирование, перемещение, удаление, корзина, ZIP-архивация и распаковка; открытие файла внешней программой. |
| `queue.rs`     | Очередь операций (`Queue`, `OpSpec`): задачи выполняются по одной в порядке добавления, ожидающие можно переставлять и отменять, упавшие — повторять. |
| `zip.rs`       | Потоковые запись и чтение ZIP (deflate / stored, имена UTF-8 или CP866). |
| `util.rs`      | `FileKind` по расширению и его цвет, `format_size`, `format_time`, смешивание цветов, `hex_dump`. |
| `theme.rs`     | Палитра (константы `Color32`), загрузка системных шрифтов, стиль egui. |
| `icons.rs`     | Иконки, нарисованные примитивами `Painter`: папки, цветные плитки файлов, контурные глифы (`Glyph`). |
| `search.rs`    | Фоновый поиск файлов (Alt+F7): маски TC и regex по имени, текст внутри файлов (`regex::bytes`, потоково блоками по 1 МБ с перекрытием), фильтры размера/даты/глубины, имена в ZIP. Результаты приходят в UI пачками через `mpsc`. |
| `app/find.rs`  | Диалог «Поиск файлов» (`Modal::Find`): форма, живой список результатов, переход к файлу, просмотр, «Файлы в панель». |
| `dnd.rs`       | Перетаскивание с ОС: вынос файлов в другие программы (`SHDoDragDrop`), положение курсора и Ctrl/Shift во время чужого перетаскивания, правила «копировать или переместить» и «можно ли сюда положить». |
| `app/drag.rs`  | Перетаскивание в окне: зоны сброса панелей (`DropZone`), подсказка у курсора, постановка копирования/перемещения в очередь. Файлы, брошенные из других программ, приходят через `RawInput::dropped_files`. |
| `logo.rs`      | Растеризация `assets/quokka.svg` через `resvg` в `IconData` / текстуру. |

## Модель состояния

```
QuokkaApp
├── sides: [Side; 2]        левая и правая панель
│   └── Side { tabs: Vec<Panel>, cur }
├── active: usize           индекс активной панели
├── dual, show_hidden       глобальные режимы (F12, F11)
├── modal: Modal            открытый диалог (не более одного)
├── queue: Queue            очередь фоновых операций (Ctrl+J — панель очереди)
├── toast: Option<Toast>    всплывающее сообщение
├── places, drives          содержимое сайдбара
└── actions: Vec<Action>    очередь действий на этот кадр
```

`Panel` с пустым `path` — это виртуальный вид «This PC» со списком дисков. Родителем корня диска на Windows считается «This PC» (`panel::parent_of`).

## Кадр (`QuokkaApp::update`)

1. `poll_queue` — опрашивает текущую задачу очереди; по завершении перечитывает все панели, показывает тост и запускает следующую задачу.
2. `handle_keys` — только когда нет диалога (`idle`); переводит нажатия в `Action`. Очередь работает в фоне и интерфейс не блокирует.
3. Отрисовка: `top_bar`, `fkey_bar`, `sidebar`, `central` (панели), `modal_ui`, `job_ui`, `toast_ui`. Виджеты не меняют состояние напрямую, а кладут `Action` в очередь.
4. Выполнение накопленных действий через `run(action)`.
5. `focus_policy` — управление фокусом клавиатуры (поиск, ввод пути).

Такая схема — «собрать действия, потом выполнить» — позволяет клавиатуре, кнопкам, F-бару и контекстному меню использовать один и тот же код в `run`.

## Действия и диалоги

`Action` — перечисление всех команд (F-клавиши, навигация, курсор, отметки, вкладки). Команды, требующие подтверждения или ввода, открывают `Modal`:

| `Modal`          | Откуда            | Что делает |
|------------------|-------------------|------------|
| `Help`           | F1                | Таблица горячих клавиш |
| `Settings`       | кнопка ⚙          | Скрытые файлы, режим панелей |
| `Input`          | F2, F7, F9        | Имя для переименования / новой папки / нового файла |
| `Transfer`       | F5, F6            | Путь назначения (по умолчанию — другая панель), флаг перезаписи |
| `ConfirmDelete`  | F8, Delete        | Подтверждение удаления |
| `Viewer`         | F3                | Текст или hex-дамп (первые 512 КБ, hex — до 64 КБ) |
| `Editor`         | F4                | Редактирование UTF-8 файла до 4 МБ |
| `Message`        | ошибки открытия   | Информационное окно |
| `Find`           | Alt+F7            | Поиск файлов. При закрытии диалог сохраняется в `QuokkaApp::find` (повторный Alt+F7 возвращает его с результатами); просмотр F3 открывается поверх, после закрытия просмотрщика поиск возвращается (`resume_find`) |

Пока открыт диалог, глобальные горячие клавиши не обрабатываются; диалог сам читает `Esc`/`Enter` и свои клавиши.

## Фоновые операции (`fsops.rs`)

- `start_copy`, `start_move`, `start_delete` запускают поток через `spawn` и сразу возвращают `Job`.
- Поток общается с UI через `mpsc`-канал сообщениями `Msg::Progress` и `Msg::Done`; `Reporter` ограничивает частоту обновлений (~50 мс) и вызывает `ctx.request_repaint()`.
- Отмена — общий `Arc<AtomicBool>`, проверяемый `Reporter::check` между файлами и между блоками больших файлов.
- Копирование считает прогресс в байтах (`Job::bytes = true`), перемещение и удаление — в элементах.
- `resolve` сопоставляет источники с целями; при нескольких источниках несуществующая цель создаётся как папка.

## Отрисовка

Таблица файлов рисуется вручную (`table` в `app.rs`): виртуальная прокрутка, столбцы Name / Modified / Size / Type (часть скрывается на узкой панели, см. `Cols`), иконки из `icons.rs`. Иконки и логотип не используют растровых ресурсов, кроме SVG, вшитого через `include_str!`.

## Известные ограничения

- Удаление идёт мимо Корзины.
- Операции очереди выполняются строго по одной; ZIP64 (архивы больше 4 ГБ) не поддерживается.
- Поиск по тексту не заглядывает внутрь архивов (в ZIP ищутся только имена); совпадение regex длиннее 4 КБ на границе блоков может быть пропущено.
- Ссылки и junction-точки при поиске не обходятся, чтобы не зациклиться.
- Настройки (скрытые файлы, режим панелей, открытые вкладки) не сохраняются между запусками.
