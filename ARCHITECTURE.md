# Архитектура Quokka File Manager

Приложение — одно окно на `eframe` (immediate-mode UI egui). Код разделён на слои по принципам чистой (гексагональной) архитектуры: зависимости направлены только внутрь, и каждый слой — отдельный крейт workspace, поэтому нарушение правила просто не скомпилируется.

```
quokka (src/, UI на egui) ──► quokka-infra ──► quokka-core ──► quokka-domain
         └──────────────────────────────────────┴──────────────────┘
```

| Крейт | Слой | Знает о | Не знает о |
|---|---|---|---|
| `crates/domain` | Домен: данные и правила | — | ФС, ОС, egui |
| `crates/core` | Приложение: сценарии и порты | domain | ФС, ОС, egui |
| `crates/infra` | Инфраструктура: адаптеры портов | domain, core | egui |
| `src/` (`quokka`) | Интерфейс и точка сборки | все слои | — |

## Модули

### `quokka-domain`

| Модуль | Ответственность |
|---|---|
| `entry.rs` | `Entry` — строка списка, `SortKey`, порядок сортировки (`compare`), фильтр имени (`Filter`: подстрока / regex), описание типа файла. Описания типов разделяются между строками (`Arc<str>`), поэтому большая папка хранит одну копию «Текстовый документ». |
| `kind.rs` | `FileKind` по расширению. |
| `format.rs` | `format_size`, `format_time`, `items_text`, `hex_dump`. |
| `paths.rs` | `parent_of` (родитель корня диска — «Этот компьютер»), `root_label`. |
| `rename.rs` | Групповое переименование: язык масок (`[N2-5]`, `[C10+5:3]`, `[Y-M-D]` …), поиск и замена, регистр, счётчик; `plan` — новые имена и проблемы (недопустимое имя, дубликат внутри пакета, занятое имя). Диск доступен только через переданную функцию `exists`. |
| `ops.rs` | `OpSpec` — что должна сделать фоновая операция, её заголовок и `touched_dirs` — какие папки она меняет. |
| `transfer.rs` | Правила перетаскивания: копировать или перемещать, можно ли бросить сюда. |

### `quokka-core`

| Модуль | Ответственность |
|---|---|
| `ports.rs` | Порты: `FileSystem` (листинг, метаданные, диски, место на диске, размер дерева), `FileOps` (запуск операций), `Watcher` (уведомления об изменениях папки); `Services` — набор адаптеров, который получает вкладка. |
| `waker.rs` | `Waker` — сигнал «перерисуй», который фоновые задачи посылают интерфейсу. UI реализует его через `egui::Context::request_repaint`. |
| `panel.rs` | `Panel` — вкладка: путь, список, курсор, отметки, фильтр, сортировка, история, размеры папок, наблюдение за папкой. |
| `listing.rs` | Чтение папки в фоне: запрос, отмена устаревших запросов, сортировка в рабочем потоке. |
| `queue.rs` | Очередь операций (`Queue`): по одной, в порядке добавления; перестановка, отмена, повтор. |
| `job.rs` | `Job` / `Reporter` — прогресс и отмена фоновой операции. |
| `folder_size.rs` | Фоновый подсчёт размеров папок вкладки. |
| `fake.rs` | (только тесты) ФС, наблюдатель и операции в памяти. |

### `quokka-infra`

| Модуль | Ответственность |
|---|---|
| `stdfs.rs` | `StdFs: FileSystem` на `std::fs`; список дисков — одним вызовом `GetLogicalDrives`. |
| `watcher.rs` | `NotifyWatcher: Watcher` на крейте `notify` (ReadDirectoryChangesW). |
| `fsops.rs` | `StdFileOps: FileOps` — копирование, перемещение, удаление, корзина, ZIP; открытие во внешней программе. |
| `rename.rs` | `rename_batch` — переименование пакета: цепочки и обмены (`a ↔ b`) через временные имена, откат при ошибке. |
| `zip.rs` | Потоковые запись и чтение ZIP (deflate / stored, имена UTF-8 или CP866). |
| `search.rs` | Фоновый поиск файлов (Alt+F7): маски TC и regex, текст внутри файлов, фильтры, имена в ZIP. |
| `clipboard.rs`, `shell_dnd.rs`, `iconsrc.rs` | Буфер обмена, перетаскивание и значки оболочки Windows. |
| `lib.rs` | `services(waker)` — рабочий набор адаптеров. |

### `quokka` (UI, `src/`)

| Модуль | Ответственность |
|---|---|
| `main.rs` | Окно и точка сборки: подключает слои под привычными именами (`panel`, `queue`, `fsops`, `search` …). |
| `app.rs` | Всё, что видно на экране: верхняя панель, сайдбар, панели с вкладками, таблица файлов, F-бар, диалоги, тосты, очередь. Клавиатура и диспетчеризация действий. |
| `app/find.rs`, `app/drag.rs`, `app/rename.rs` | Диалог поиска; перетаскивание внутри окна; диалог группового переименования. |
| `tray.rs` | Windows: значок в трее (окно подклассируется, клики приходят без кадров egui), скрытие окна в трей, режим одного экземпляра (мьютекс + `WM_COPYDATA` с папкой). |
| `file_icons.rs` | Кэш значков Windows: по расширению, по файлу — только для `exe`, `lnk`, `ico` и подобных. |
| `config.rs` | Настройки, места сайдбара и сеанс — вкладки обеих панелей. |
| `theme.rs`, `icons.rs`, `util.rs`, `logo.rs`, `dnd.rs` | Палитра и шрифты, нарисованные иконки, цвета типов файлов, логотип, связка перетаскивания с окном. |

## Производительность

- **Папки читаются в фоне.** `Panel` запускает `listing::start` и ждёт результат не дольше 30 мс. Обычная папка появляется в том же кадре, а большая, сетевая или медленная показывает «Загрузка…», и окно продолжает отвечать. Устаревший запрос (пользователь уже ушёл в другую папку) отменяется, его результат отбрасывается. Действия, которым нужен новый список (выделить имя, поставить курсор), откладываются до его прихода.
- **Переход в папку** проверяет, что она открывается, но ждёт ответа не дольше 400 мс. Мёртвый сетевой ресурс больше не замораживает окно: ошибку покажет сам листинг.
- **Обновление — по изменениям, а не целиком.** Видимые вкладки следят за своей папкой (`Watcher`) и обновляются сами, не чаще раза в 250 мс; для больших папок пауза растёт до 4× времени листинга. Во время обновления на экране остаются прежние строки. После операции из очереди обновляются только вкладки с затронутыми папками (`OpSpec::touched_dirs`). Скрытые вкладки лишь помечаются `stale` и перечитываются, когда их покажут.
- **Фильтр не пересортировывает список** (`apply_filter`), сортировка выполняется в потоке листинга.
- **Значки** кэшируются по расширению: на 10 000 `.txt` приходится один вызов оболочки и одна текстура.
- **Место на дисках** для подсказок сайдбара считается в фоне, а не в каждом кадре.

Замер (`cargo test -p quokka-infra --release --test big_folder -- --ignored --nocapture`), 50 000 файлов: листинг ≈ 45 мс, окно занято ≤ 36 мс, фильтр ≈ 1,5 мс, пересортировка ≈ 2 мс.

## Модель состояния

```
QuokkaApp
├── sides: [Side; 2]        левая и правая панель
│   └── Side { tabs: Vec<Panel>, cur }
├── active: usize           индекс активной панели
├── dual, show_hidden       глобальные режимы (F12, F11)
├── modal: Modal            открытый диалог (не более одного)
├── queue: Queue            очередь фоновых операций (Ctrl+J — панель очереди)
├── toast: Option<Toast>    всплывающее сообщение
├── places, drives          содержимое сайдбара
└── actions: Vec<Action>    очередь действий на этот кадр
```

`Panel` с пустым `path` — это виртуальный вид «This PC» со списком дисков. Родителем корня диска на Windows считается «This PC» (`quokka_domain::paths::parent_of`).

## Кадр (`QuokkaApp::update`)

1. `poll_queue` — опрашивает текущую задачу очереди; по завершении обновляет вкладки с затронутыми папками, показывает тост и запускает следующую задачу. Затем каждая вкладка вызывает `Panel::poll`: забирает готовый листинг и размеры папок, обновляется после изменений на диске.
2. `handle_keys` — только когда нет диалога (`idle`); переводит нажатия в `Action`. Очередь работает в фоне и интерфейс не блокирует.
3. Отрисовка: `top_bar`, `fkey_bar`, `sidebar`, `central` (панели), `modal_ui`, `job_ui`, `toast_ui`. Виджеты не меняют состояние напрямую, а кладут `Action` в очередь.
4. Выполнение накопленных действий через `run(action)`.
5. `focus_policy` — управление фокусом клавиатуры (поиск, ввод пути).

Такая схема — «собрать действия, потом выполнить» — позволяет клавиатуре, кнопкам, F-бару и контекстному меню использовать один и тот же код в `run`.

## Действия и диалоги

`Action` — перечисление всех команд (F-клавиши, навигация, курсор, отметки, вкладки). Команды, требующие подтверждения или ввода, открывают `Modal`:

| `Modal`          | Откуда            | Что делает |
|------------------|-------------------|------------|
| `Help`           | F1                | Таблица горячих клавиш |
| `Settings`       | кнопка ⚙          | Скрытые файлы, режим панелей |
| `Input`          | F2, F7, F9        | Имя для переименования / новой папки / нового файла |
| `Transfer`       | F5, F6            | Путь назначения (по умолчанию — другая панель), флаг перезаписи |
| `ConfirmDelete`  | F8, Delete        | Подтверждение удаления |
| `Viewer`         | F3                | Текст или hex-дамп (первые 512 КБ, hex — до 64 КБ) |
| `Editor`         | F4                | Редактирование UTF-8 файла до 4 МБ |
| `Message`        | ошибки открытия   | Информационное окно |
| `MultiRename`    | Ctrl+M, F2 при нескольких отмеченных | Групповое переименование с предпросмотром; результат можно отменить Ctrl+Z (`Undo::Rename`) |
| `Find`           | Alt+F7            | Поиск файлов. При закрытии диалог сохраняется в `QuokkaApp::find` (повторный Alt+F7 возвращает его с результатами); просмотр F3 открывается поверх, после закрытия просмотрщика поиск возвращается (`resume_find`) |

Пока открыт диалог, глобальные горячие клавиши не обрабатываются; диалог сам читает `Esc`/`Enter` и свои клавиши.

## Фоновые операции (`core/job.rs`, `infra/fsops.rs`)

- Очередь вызывает порт `FileOps::start(spec, waker)`; адаптер `StdFileOps` запускает поток через `Job::spawn` и сразу возвращает `Job`.
- Поток общается с UI через `mpsc`-канал сообщениями `Msg::Progress` и `Msg::Done`; `Reporter` ограничивает частоту обновлений (~50 мс) и вызывает `Waker::wake()`.
- Отмена — общий `Arc<AtomicBool>`, проверяемый `Reporter::check` между файлами и между блоками больших файлов.
- Копирование считает прогресс в байтах (`Job::bytes = true`), перемещение и удаление — в элементах.
- `resolve` сопоставляет источники с целями; при нескольких источниках несуществующая цель создаётся как папка.

## Тесты

- `quokka-domain` — чистые функции: сортировка, фильтр, правила перетаскивания, `OpSpec`.
- `quokka-core` — `Panel` и `Queue` проверяются на `fake.rs` (ФС, наблюдатель и операции в памяти), без диска и без egui.
- `quokka-infra` — адаптеры на временных папках; `tests/big_folder.rs` — замер на 50 000 файлов (`#[ignore]`, запускается вручную).
- `quokka` — разбор клавиш, настройки, кэш значков.

Все тесты: `cargo test --workspace`.

## Отрисовка

Таблица файлов рисуется вручную (`table` в `app.rs`): виртуальная прокрутка, столбцы Name / Modified / Size / Type (часть скрывается на узкой панели, см. `Cols`), иконки из `icons.rs` или значки Windows из `file_icons.rs`. Иконки и логотип не используют растровых ресурсов, кроме SVG, вшитого через `include_str!`.

## Известные ограничения

- ZIP-папки реализованы адаптером `infra::archive`: виртуальный путь `archive.zip/member/path`, листинг через `StdFs` читает только центральный каталог. Обычный `Panel` сохраняет сортировку, фильтр и историю. Копирование виртуальных элементов извлекает их в фоновом задании с CRC и временным файлом перед заменой назначения; изменение архива запрещено в UI и адаптере операций. Вложенные ZIP и другие форматы пока не открываются как папки.
- `src/app/preview.rs` читает текст и декодирует фотографии в рабочем потоке. Ограничены размер входа, память декодера и размер GPU-текстуры; закрытие просмотрщика отменяет дальнейшую работу, уже начатое декодирование завершается в фоне.
- Операции очереди выполняются строго по одной; ZIP64 (архивы больше 4 ГБ) не поддерживается.
- Поиск по тексту не заглядывает внутрь архивов (в ZIP ищутся только имена); совпадение regex длиннее 4 КБ на границе блоков может быть пропущено.
- Ссылки и junction-точки при поиске не обходятся, чтобы не зациклиться.
- Открытые вкладки, в том числе ZIP-папки, сохраняются между запусками при включённом восстановлении сеанса (настройки хранятся в `%APPDATA%`, см. `config.rs`).
